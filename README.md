# Portfolio

Public, static-first home for small, practical web-development demos.

## Status

Four live browser-based demos are available:

- [JSON → CSV Converter](https://portfolio-rjm.pages.dev/demos/json-csv/) — flat JSON conversion with preview, copy and download.
- [Shopify CSV Validator](https://portfolio-rjm.pages.dev/demos/shopify-csv/) — focused product CSV checks before import, not complete Shopify compatibility validation.
- [Mobile Checkout](https://portfolio-rjm.pages.dev/demos/mobile-checkout/) — mock-only checkout interactions with quantities, delivery/pickup, promo codes and form validation; no real orders or payments.
- [Pagination & Duplicate Data Fixer](https://portfolio-rjm.pages.dev/demos/pagination-fixer/) — synthetic paginated products with overlapping records, rapid refreshes, stale and out-of-order responses; compare naive append behavior with a guarded, ID-deduplicated list. This URL becomes available only after authorized publication.

## Tech stack

- React + TypeScript with Vite, producing a static `dist/` output; no server or database.
- pnpm 11.26.0 and Node.js 24.
- Biome for formatting and lint checks, Vitest for tests, GitHub Actions for PR checks.

The homepage presents live demos from `src/demos/catalog.ts`; planned entries stay hidden. Each demo is an independent static page.

## Run locally

Install Node.js 24 and pnpm 11.26.0, then:

```sh
pnpm install
pnpm dev
```

Quality checks:

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

`pnpm build` generates `dist/`. The committed `pnpm-lock.yaml` was generated by the Node 24 / pnpm 11 CI runner and is used with `pnpm install --frozen-lockfile` to keep installations reproducible. Changes to dependencies must update the lockfile in the same PR.

## Collaboration and public repository boundaries

- `AGENTS.md` is the entry point for coding agents.
- `.codex/chatgpt/project-instructions.md` is the source for ChatGPT Project setup; it does not auto-sync into ChatGPT settings.
- `docs/collaboration.md` is Portfolio's single Collaboration owner, integrating useful donor alignment and collaboration guidance.
- `.agents/skills/execute-plan/SKILL.md` is the callable Execution owner for direct bounded changes.
- `.codex/project-collaboration/contracts/implementation-review.md` owns independent Review semantics, invoked by `.agents/skills/implementation-review/SKILL.md`.
- Generic design/tooling principles, the Handoff contract and coding safety/quality rules are conditional supporting material. Skill discoverability needs an actual fresh Codex actor-session probe; file presence does not prove invocation.
- `.codex/project-memory/decisions.md` records durable accepted decisions only.

Do not publish customer data, private project artifacts, API keys, analytics tokens, or unapproved personal information.

## Add an independent demo

Each demo has a real static page at `/demos/<slug>/`. Add these two entrypoints;
Vite discovers `demos/*/index.html` automatically at build time, so no Vite config
or other demo files need editing:

```text
demos/example/index.html
src/demos/example/main.tsx
```

For example, `demos/example/index.html`:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Example demo</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/demos/example/main.tsx"></script>
  </body>
</html>
```

And `src/demos/example/main.tsx`:

```tsx
import { createRoot } from 'react-dom/client';

const root = document.getElementById('root');
if (!root) throw new Error('Missing #root element');
createRoot(root).render(<h1>Example demo</h1>);
```

Keep the demo's implementation, styles, fixtures, and tests under its own
`src/demos/<slug>/` directory. Use lowercase hyphenated slugs. Restart the build
when adding HTML entries. The example above is documentation, not a published demo.

Run the four quality checks above. `pnpm build` retains `dist/index.html` and emits
`dist/demos/example/index.html` plus its bundled assets. With `pnpm dev` or
`pnpm preview`, visit `/demos/example/` directly. A static host serving `dist/`
from the domain root must support ordinary directory index files; no SPA fallback
or provider-specific rewrite is required for direct visits and refreshes.

`tests/static-entrypoints.test.ts` builds two temporary demo entries and checks
that the homepage, nested HTML pages, and referenced JavaScript assets exist.
This verifies build output, not browser behavior or a deployed host.

Keep `src/demos/catalog.ts` entries `planned` until the corresponding page works
and passes review. An implementation PR may update only its own record to `live`
with `href: '/demos/<slug>/'`; rebase if another demo PR lands first. Do not add
shared feature logic or dependencies without a concrete second consumer.
